# 协作移交说明

本文用于项目移交。接手同学应先阅读本文，再看 `README.md`、`docs/dev-setup.md`、`docs/development-roadmap.md`、`需求规格说明书.md` 和 `实现设计说明书.md`。

## 当前阶段结论

项目已经具备基础电商闭环和联调用前端工作台，可以作为后续多人协作开发的基础版本。

已具备的主链路：

- 普通用户注册、登录、登出、资料编辑、头像上传、地址增删改查。
- 商家自助入驻、平台审核、审核通过后创建店铺并绑定商家账号。
- 平台分类管理、商家商品和 SKU 管理、商品多图和图文详情、商品收藏、店铺关注。
- 购物车、跨店结算、优惠券、满减、积分抵扣、支付宝沙箱扫码支付。
- 订单列表、支付单查询、商家发货、用户确认收货、按订单明细评价。
- 售后按订单明细和数量申请，商家和平台可处理售后。
- 社区发帖、评论、点赞、分区、话题、用户主页、关联商品卡片、平台内容隐藏。
- 种草帖来源加购、确认收货后给推广人和下单者发放积分奖励。
- 拼团专区、商家拼团活动、用户开团和参团、支付宝支付后成团流转。

用户端前端已完成路由拆分，从单体测试控制台拆为 11 个独立页面（含商品详情独立路由共 13 条路由），路由结构为：`/` 首页、`/login` 登录、`/register` 注册、`/products` 商品列表、`/products/:productId` 商品详情、`/group-buy` 拼团、`/cart` 购物车、`/checkout` 结算、`/orders` 订单、`/community` 社区、`/promotions` 优惠券、`/addresses` 地址、`/user` 用户中心、`/merchants/:merchantId` 店铺主页。原测试控制台代码保留在 `user-frontend/src/pages/test-console/index.tsx` 作为功能完整性参考，不再被路由引用。管理端仍是联调工作台，需要在后续迭代中拆分平台端和商家端。

## 不要继续做的旧方案

- 不接入微信支付。
- 正常前端业务不使用 mock 支付，只使用支付宝沙箱扫码支付。
- 不实现真实物流轨迹查询，只做商家发货、用户确认收货。
- 不实现售后取消。
- 不做商品迁移功能。
- 不做品牌体系，只保留营销标签。
- 商品、帖子、评论、评价不做事前审核，采用发布后治理；只有商家入驻需要审核。

## 支付说明

支付仅使用支付宝沙箱扫码支付。

- 沙箱网关：`https://openapi-sandbox.dl.alipaydev.com/gateway.do`
- 预创建接口：`POST /api/v1/payments/{payment_id}/alipay/precreate`
- 支付同步接口：`POST /api/v1/payments/{payment_id}/alipay/sync`
- 异步通知接口：`POST /api/v1/payments/notify/alipay`

`.env` 中需要配置支付宝 App ID、应用私钥、支付宝公钥和 notify URL。私钥不得提交到 GitHub。

## 后续开发总原则

1. 后端扩展新功能时，前端必须同轮补充页面入口、表单、列表、按钮或状态展示。
2. 接口字段、权限、状态、错误码或价格规则变化时，同步更新 `docs/api/*.md`。
3. 每个模块后续都按完整需求实现，不再只做占位或最小闭环。
4. 业务结果必须展示在页面业务区，接口 JSON 返回只作为排查工具。
5. 普通用户、商家运营、平台运营的 token、页面和权限必须分离。

## 后续重点任务

### 1. 前端最终迭代

目标：把当前联调工作台拆成正式 PC 端页面，并保留现有接口调用能力。

**用户端已完成路由拆分（2026-07-03）**：原 129KB 单体测试控制台已按业务域拆为 11 个独立页面，所有接口调用能力保留。已完成页面：

- 首页 `/`：快捷入口卡片，登录态判断，导航到商品、拼团、订单、社区等模块。
- 商品列表页 `/products`：分类树、搜索、价格筛选、排序、分页列表，点击卡片跳转详情。
- 商品详情页 `/products/:productId`：多图、SKU 选择、加购、收藏、图文详情、评价区（评分筛选、只看有图）、店铺入口。
- 拼团页 `/group-buy`：活动列表、开团/参团、地址选择、积分抵扣、支付宝二维码。
- 购物车 `/cart`：勾选、数量修改、删除、批量操作、失效商品提示、种草来源展示、合计。
- 结算页 `/checkout`：地址选择、满减、优惠券、积分抵扣、支付宝二维码、支付单/订单 ID 展示。
- 订单页 `/orders`：列表分页、状态筛选、支付单、支付宝二维码、确认收货、取消、评价、售后。
- 社区页 `/community`：分区切换、话题筛选、帖子列表、详情 Drawer、发帖、评论、点赞、用户主页 Modal、种草来源下单。
- 优惠券页 `/promotions`：可领券模板列表、我的券列表、领取。
- 地址页 `/addresses`：Ant Design Form 增删改查、设默认、Popconfirm 删除确认。
- 用户中心 `/user`：资料编辑、头像上传、积分账户、积分流水、会员等级、签到、商品收藏、关注店铺。
- 登录 `/login`、注册 `/register`、店铺主页 `/merchants/:merchantId`。

公共工具函数已提取到 `user-frontend/src/utils/format.ts`，所有页面共用。

**用户端后续优化方向**（可选，不影响功能完整性）：

- 店铺主页可补充店铺活动、店铺社区动态。
- 视觉风格统一升级（当前为 Ant Design 默认风格）。
- 路由级懒加载优化首屏加载。

**管理端仍需拆分**（待迭代）：

- 平台运营：商家入驻、分类、商品监管、订单、售后、促销、社区治理、用户、操作日志、报表。
- 商家运营：店铺资料、商品、SKU、库存、订单发货、售后、优惠券、满减、拼团、商家动态、经营概览。

前端迭代时可以调整视觉，但不要删除现有关键接口调用；原测试控制台代码保留在 `user-frontend/src/pages/test-console/index.tsx` 作为功能清单参考。

### 2. 后台报表与数据可视化

目标：在管理端补齐平台和商家的经营数据看板。

后端建议新增聚合接口：

- 平台汇总：GMV、支付订单数、新增用户数、新增商家数、售后数、退款金额。
- 商家汇总：本店 GMV、订单数、待发货、售后数、商品数、转化相关数据。
- 趋势图：近 7/30 天 GMV、订单量、退款量。
- 分布图：订单状态分布、售后状态分布、支付金额区间。
- 排行榜：商品销量 TOP、销售额 TOP、店铺销售 TOP、社区种草转化 TOP。
- 促销效果：券领取量、使用量、核销金额、满减优惠金额、拼团成团率。
- 会员积分：新增会员、积分发放、积分消耗、种草奖励。
- 社区转化：帖子数、评论数、点赞数、种草来源订单数、种草奖励积分。

权限要求：

- 平台可看全平台。
- 商家只能看本店数据，不能通过参数越权查看其它店铺。

### 3. 客服与 WebSocket

目标：实现用户与商家的基础客服会话，并支持订单或售后上下文。

建议后端模型：

- `customer_service_conversation`：会话，包含用户、商家、关联商品、关联订单、状态。
- `customer_service_message`：消息，包含发送者类型、发送者 ID、文本、图片、已读状态。

建议 WebSocket：

- `/ws/chat/{conversation_id}?token=xxx`
- 消息类型：`chat.send`、`chat.message`、`chat.read`、`conversation.closed`、`ping`、`pong`、`error`

要求：

- 消息必须持久化，WebSocket 只负责实时推送。
- 用户只能进入自己的会话。
- 商家只能进入本店会话。
- 平台后续可作为监管角色查看或介入。

### 4. 剩余业务硬化

- 拼团过期失败处理、退款和积分回退。
- 限时价和营销标签。
- 会员等级权益、签到、积分账户页。
- 售后退款后优惠券、积分、库存和订单状态联动。
- SKU 规格模板、批量维护。
- 社区话题治理、话题合并、话题隐藏。
- 导出能力、操作日志覆盖范围、筛选增强。
