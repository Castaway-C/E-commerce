# 后续维护与优化计划

当前项目已经完成主要业务功能。后续工作不再以“大模块补齐”为主，而是围绕答辩展示、前端交互、测试补强和少量智能化扩展进行维护。

## 1. 前端交互优化

- 统一页面空状态、加载态、错误提示和表单校验文案。
- 优化用户中心、订单详情、客服消息、社区详情和报表页面的可读性。
- 检查所有用户可见状态文案，确保使用中文业务文案。
- 优化商品选择器、图片预览、分页、筛选重置、批量操作等高频交互。
- 当前主要面向 PC 端展示，移动端可作为后续扩展。

## 2. 答辩与演示数据

- 准备至少 2 个商家、若干分类、商品、SKU、优惠券、满减、拼团活动。
- 准备多种订单状态：待支付、待发货、待收货、已完成、售后中。
- 准备社区普通帖、种草帖、商家动态和评论数据。
- 准备平台和商家报表可见的数据量，避免演示时图表为空。
- 支付宝沙箱演示前确认买家账号、网关、App ID 和密钥属于同一沙箱环境。

## 3. 测试补强

优先补以下流程的自动化或手工验收记录：

- 跨店订单金额拆分、支付单关联和库存变化。
- 满减、优惠券、积分抵扣和会员等级配置的计算顺序。
- 支付宝二维码重复生成、支付同步和异步通知幂等。
- 售后按订单明细和数量申请、处理和状态变化。
- 拼团开团、参团、成团、库存和积分抵扣。
- 客服会话权限：平台、商家、用户各自只能看到自己的会话范围。
- 社区种草来源加购和确认收货后的积分奖励。

## 4. AI 助手扩展

当前 AI 助手已接入 qwen-flash，主要基于预设提示词回答商城规则。后续可逐步扩展：

- 读取公开商品、店铺、分类、促销、拼团活动等数据，提供导购建议。
- 在用户登录后读取本人的订单状态、优惠券和积分信息，回答个人化问题。
- 在平台和商家客服工作台中生成回复草稿，由人工确认后发送。
- 增加能力开关接口，让前端根据模型配置决定显示完整助手或降级提示。

AI 扩展仍应保持权限边界，关键业务状态由用户、商家或平台运营确认后变更。

## 5. 报表扩展

- 增加时间范围筛选和图表说明。
- 增加订单、售后、促销、积分、社区互动等指标口径说明。
- 平台报表保持全局视角，商家报表保持本店视角。
- 导出字段可按答辩或报告需要继续补充。

## 6. 基础设施

- 当前开发和答辩环境使用 MySQL，模型稳定后可引入 Alembic 做正式迁移。
- Redis 可继续用于 Celery、token 黑名单、热点缓存和消息通知。
- WebSocket 可继续扩展客服已读状态、图片消息、系统通知。
- 上传能力可补文件大小、类型限制和定期清理策略。
