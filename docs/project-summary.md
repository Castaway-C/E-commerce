# 项目总结

## 项目简介

一次买够（It's Mygo）是一个社交新零售电商平台实训项目。项目围绕普通用户、商家运营和平台运营三类角色，完成了电商交易、商家入驻、商品管理、购物车、订单支付、促销积分、拼团、社区种草、售后、客服、报表和 AI 助手等模块。

项目特点是业务链路较完整，不只是单一商城页面，而是覆盖了平台运营、商家经营和用户消费的多角色闭环。

## 已完成能力

- 用户端商城：游客浏览、商品搜索、分类筛选、商品详情、店铺主页、收藏、关注。
- 交易链路：购物车、跨店下单、支付宝沙箱支付、发货、收货、评价、售后。
- 商家后台：入驻、店铺资料、商品 SKU、库存、促销、拼团、订单、售后、客服和报表。
- 平台后台：商家审核、分类、首页轮播、商品监管、用户、订单、售后、社区治理、会员积分配置和报表。
- 促销体系：优惠券、满减、积分抵扣、会员等级配置和积分流水。
- 社区体系：发帖、评论、点赞、收藏、话题、用户主页、关联商品、种草来源和积分奖励。
- 拼团体系：商家配置活动、用户开团/参团、成团后发货。
- 客服体系：用户、平台和商家会话，商品和订单场景客服弹窗。
- AI 助手：基于 qwen-flash 的悬浮购物助手最小版。

## 技术收获

- 熟悉了 FastAPI 项目的分层组织方式。
- 学习了 SQLAlchemy async、Pydantic schema、JWT 认证和角色权限控制。
- 实践了 React + TypeScript + Ant Design 的中大型页面组织。
- 完成了跨端接口协作、统一响应、分页、错误码和文档维护。
- 接入了支付宝沙箱扫码支付，理解了预创建、二维码、同步查询和异步通知。
- 通过 Celery 设计了订单超时、优惠券过期、自动确认收货等任务。
- 通过社区种草、积分奖励、拼团和促销规则练习了复杂业务状态处理。

## 项目亮点

1. 多角色分离清晰：用户端、平台端、商家端账号和权限互不混用。
2. 电商链路完整：从商品浏览到支付、履约、评价、售后均可演示。
3. 社交与交易结合：社区种草可关联商品并影响购物车来源和积分奖励。
4. 促销规则较完整：满减、优惠券、积分、会员等级按明确顺序计算。
5. 支付接入真实沙箱：不是简单模拟支付，而是对接支付宝沙箱扫码。
6. 后台运营能力完整：平台和商家均具备管理、客服和报表视角。
7. 具备 AI 扩展入口：已接入 qwen-flash，为后续智能导购和客服建议回复预留空间。

## 当前边界

- 当前主要面向 PC 端展示，移动端适配不是重点。
- AI 助手当前是最小版，不读取实时业务数据。
- 报表以已有业务数据为主，后续可继续深化指标口径。
- 物流记录快递公司和单号，用于演示发货/收货流程。
- 数据库迁移当前以开发环境自动建表为主，后续生产化可补 Alembic。

- 为答辩准备稳定的演示数据和演示脚本。
